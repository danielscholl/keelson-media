# your-agent-drives-it (FIG. 15)

**Concept (what, why, how):** what: Keelson serves its tool registry over MCP at `/api/mcp`, so an external coding agent can run workflows and rib tools. Why: keep the agent you already use for the conversation, and let Keelson keep the durable parts (workflows, gates, the run record, ribs and their credentials). How: tools run inside the Keelson server with each rib's own credentials, so the agent never sees the secrets; `keelson connect claude|copilot|codex` wires the endpoint into the agent's own config and adds a small skill, `disconnect` reverses it; the endpoint is open on loopback by default and can be made read-only, token-gated, or filtered by tool name.

**Structure:** the lay-the-keel opener with "Figure fifteen. Your agent drives it.", a gateway board (agents, MCP, the server, the registry, credentials staying inside), Claude Code in the harbor repo told to run a workflow through Keelson (its MCP calls shown as `● keelson workflow_list` / `workflow_run`), the run appearing live in Keelson's Runs view and completing, Claude reading the result back and questioning the report's "next high", a connect board, a why board and "Bring your agent. Keelson does the keeping." Closer with SHEET 15 · ACT IV.
