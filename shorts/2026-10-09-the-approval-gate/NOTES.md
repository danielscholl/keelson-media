# the-approval-gate (FIG. 06)

**Concept (what, why, how):** what: two gates that hold a step until a person says yes, a policy `ask` on a tool call and an `approval` node in a workflow. Why: nothing you can't undo should happen on a model's say so, and a forgotten prompt should fail closed. How: every tool call from chat, a workflow node, a rib agent, or an MCP caller passes one ordered policy engine whose policies answer allow, deny, or ask (`KEELSON_ASK_ON_SHELL=1` turns on the shell ask; an unanswered ask rejects after five minutes); an approval node holds the run before the irreversible step, and with `capture_response` the reply becomes the node's output.

**Structure:** two gates, small then large. The lay-the-keel opener with "Figure six. The approval gate.", a board of the policy engine (four callers, the builtin stack, allow/deny/ask, a person, the timeout), a chat in the harbor project asking to run the tests where the Bash call stops on an Approval needed card and runs only after Accept, a board of a gate in the graph (test, plan, gate, ship with `git tag`), a release workflow run from the terminal that pauses at the gate, the plan opening for review in the browser and the approval, the terminal finishing and `git tag` showing v0.1.0, then a why board and "Ask first. Then act." Closer with SHEET 06 · ACT II.

**Capture:** the isolated stage `/Users/Shared/keelson-demo` (port 7979), restarted with `KEELSON_ASK_ON_SHELL=1`, in the `harbor` repo. The workflow is `harbor/.keelson/workflows/tide-release.yaml` (in that repo, untracked): test and changes, a tool-less plan prompt, a bash node that writes the plan to `$KEELSON_ARTIFACTS_DIR/plan.md` so the gate's review drawer opens on it, the gate, and `git tag v0.1.0`. The terminal take (`source/release.tape`) and the browser approval (`source/rec-gate.mjs`) were recorded together; the chat take is `source/rec-chat.mjs`. The tag was deleted and the run cleared between attempts.

Findings while staging: with ask-on-shell on, the plan prompt node itself reached for Bash and blocked on a workflow-surface approval, so the plan node now has `allowed_tools: []`; approval messages are not substituted, so `$plan.output` stayed literal and the terminal prints `$ARTIFACTS_DIR/plan.md` as text; the browser resolves it into the plan drawer.

**Weak:** 120 s. The line over the chat approval card is uncaptioned on purpose (the card says it, and a caption would cover it). The terminal's pause line shows the literal `$ARTIFACTS_DIR/plan.md`. The plan text in the drawer is small at phone size even zoomed.
