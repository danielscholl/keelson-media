# what-a-swarm-is (DET. 01)

**Concept (what, why, how):** what: a swarm is a lead that owns the outcome, workers it spawns as the work calls for them, and a channel they talk in; an agent is an identity, an inbox and a resumable session, not a process. Why: some work needs more than one view, and a person should be able to read along. How: a dispatcher wakes an agent only when a message reaches it, and each wake is one turn on that agent's resumed session.

**Structure:** the lay-the-keel opener with "Swarm detail one. What a swarm is." and the problem; a crew board (one agent faded beside a lead, two workers, the channel and you reading along); an agent board (a process box crossed out, then identity, inbox and session cards, the dispatcher, a message waking one turn); the real run: launcher typed and started on Scout, the live card with the lead alone, then two advocate faces arriving, the ClickClack channel, the Done view (meters, then the Outcome); a team-not-pipeline board with a DET. 02 banner; the closer with DETAIL 01 · SWARM · ACT I.

**Capture:** the demo stage rebuilt at `~/keelson-demo/.keelson` (Keelson 0.127.0, rib-swarm 0.29.0 only; `/Users/Shared/keelson-demo` no longer existed), port 7979, managed ClickClack on 18080. One real Scout swarm, s9s2p, no project, started from the launcher on camera by `source/rec-run.mjs`, which records Keelson and ClickClack at once and takes steering commands mid-run. Done in 44 s, 12 turns, 44k tokens, $0.0970 list price. The live card worked: lead alone at start, both advocates' faces 6.5 s after Start. `source/seg.py` cuts the windows the manifest uses out of the one long take.
