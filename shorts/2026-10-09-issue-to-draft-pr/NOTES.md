# issue-to-draft-pr (FIG. 08)

**Concept (what, why, how):** what: the fix-issue starter takes a GitHub issue to a draft pull request. Why: handing an agent real code work is only safe if it can't write before a person approves the plan, can't touch the checkout you're working in, and can't open a PR over failing checks. How: everything before the approval gate reads and thinks (fetch, classify, plan, a criteria-coverage check); everything after writes; the run gets its own git worktree on a `keelson/<workflow>/<run>` branch, implements, runs the project's own checks, self-fixes, refuses to open a PR over broken checks (the hard gate), opens a draft, then three parallel reviewers and a triage judge confirm or drop findings.

**Structure:** one long real run, cut to its beats. The lay-the-keel opener with "Figure eight. Issue to draft PR.", a board of the read-and-think and write halves with the gate on the seam, a clean `main` checkout and the run started on issue #1, the pause with the criteria-coverage list, the plan approved in the browser drawer (the plan cites the project's UTC convention from the notebook), a board of the worktree beside the untouched checkout, checks passing and the draft PR opening, the parallel review lanes and triage, the run finishing as CI unverified with the PR left a draft, the checkout still clean on `main` with the new branch beside it, `gh pr list` showing #2, then a why board and the recap. Closer with SHEET 08 · ACT II.
